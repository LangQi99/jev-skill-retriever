# Graphify Structural Risk for Skill Scoring

**Proposal PR #2** — stacks on PR #1's session-depth multiplier mechanism.
**Branch:** `feat/graphify-structural-risk`

## Problem

The composer scores skills against the user's text query, but has no awareness of the
codebase's actual structure. It can't distinguish "editing a leaf file" from "editing a
god node with 40 dependents" — even though the blast radius differs enormously.

Graphify already builds this structural knowledge as a cached static graph (884 nodes,
1673 edges, 65 communities per repo). It sits on disk unused at runtime.

## Proposal

Add a **structural risk multiplier** to the composer's scoring, sourced from graphify's
cached output:

```
score = base_score × session_depth_multiplier × structural_risk_multiplier
```

The composer's pre-filter detects structural signals in the user message (file paths,
module names, refactoring keywords) and lazy-loads a ~1KB condensed index. Only the
index loads — not the full 884-node graph. Shallow sessions cost nothing.

## Index Format (generated by graphify, committed or cached)

```json
{
  "god_nodes": ["src/core/module.py", "src/api/handler.py"],
  "community_hubs": ["src/plugins/registry.py", ...],
  "file_risk": {
    "src/core/module.py": 1.5,
    "src/plugins/ui.py": 1.3
  },
  "default_risk": 1.0
}
```

## Multiplier Matrix

| Signal detected | Structural risk mult | Stacks with depth mult? |
|---------------|---------------------|------------------------|
| None (shallow query) | 1.0× (no load) | N/A |
| Leaf file path in query | 1.0× | Yes |
| Community hub file | 1.3× | Yes |
| God node file | 1.5× | Yes |
| "refactor" "dependency" etc. | 1.2× (generic) | Yes |

## Touch Points

- **New file**: graphify index format (one-time, graphify's first downstream consumer)
- **`compose.py`**: `_score_skill()` — add `structural_risk_multiplier` alongside `session_depth_multiplier`
- **`compose.py`**: pre-filter — detect file paths and structural keywords
- **`__init__.py`**: `_on_pre_llm_call()` — pass graphify index path to composer (optional, falls back to skip)

## Edge Cases

- **No graphify index exists**: gracefully skip, score = depth_multiplier only
- **File not in index**: use `default_risk = 1.0`
- **Multiple files in scope**: take the max risk (conservative)

## Relationship to PR #1

PR #1 (`feat/session-depth-quality-boost`) introduces the multiplier pattern and
threshold gating in `_score_skill()`. This PR adds a second signal source into the
same mechanism. They compose: `score *= depth_factor * structural_factor`.
